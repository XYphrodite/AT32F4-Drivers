# Документация по протоколам пакетов

В этом документе описаны протоколы пакетов, используемые в `PacketWrapper.cpp` для LoRaWAN и связанной коммуникации. Код поддерживает несколько форматов пакетов, выбираемых с помощью препроцессорных директив:
- `CayenneLPP_PACKET`
- `TINY_PACKET`
- `EXTRA_SMALL_PACKET`

## 1. CayenneLPP_PACKET

**Формат:** [Cayenne Low Power Payload (LPP)](https://community.mydevices.com/t/cayenne-lpp-cayenne-low-power-payload/7510)

- **Префикс:** `0x10` (код)
- **Версия:** `0x01`
- **Серийный номер:** 4 байта (uint32_t)
- **Полезная нагрузка:** Буфер CayenneLPP (переменный размер, обычно 16 байт в этой реализации)

**Поля:**
| Поле          | Размер (байт) | Описание                              |
|-------------- |-------------- |---------------------------------------|
| Код           | 1             | Тип пакета (0x10)                     |
| Версия        | 1             | Версия протокола (1)                  |
| Серийный номер| 4             | Серийный номер устройства             |
| Payload       | переменный    | Данные датчиков в формате CayenneLPP  |

**Формирование:**
- Используется класс `CayenneLPP` для кодирования данных датчиков.
- Серийный номер получается через `ModemConfig::GetSerialNum()`.

---

## 2. TINY_PACKET

**Формат:** Пользовательский компактный бинарный протокол (TafcoTinyProtocol, версия 2)

- **Префикс:** `0x10` (код)
- **Версия:** `0x02`
- **Серийный номер:** 4 байта (uint32_t)
- **Полезная нагрузка:** Структура `TafcoTinyProtocol` (размер 5 байт)

**Поля:**
| Поле          | Размер (байт) | Описание                              |
|-------------- |-------------- |---------------------------------------|
| Код           | 1             | Тип пакета (0x10)                     |
| Версия        | 1             | Версия протокола (2)                  |
| Серийный номер| 4             | Серийный номер устройства             |
| Payload       | 5             | Структура данных датчиков             |

**Формирование:**
- Для заполнения структуры используется функция `TafcoTinyProtocol_Create(metrics)`.
- Серийный номер получается через `ModemConfig::GetSerialNum()`.

**Кодирование ошибочных значений:**
- Если значение напряжения некорректно (NaN в коде), оно кодируется как `0xFF` в структуре протокола.
- При декодировании значение `0xFF` в поле напряжения интерпретируется как NaN (ошибка/некорректное значение).
- Если значение температуры некорректно (установлено в -100.0 в коде), оно кодируется как -100.0 в структуре протокола.
- При декодировании значение -100.0 в поле температуры интерпретируется как ошибка/некорректное значение.

---

## 3. EXTRA_SMALL_PACKET

**Формат:** Ультра-компактный бинарный протокол (TafcoTinyProtocol, короткий серийный номер)

- **Префикс:** `0x11` (код)
- **Серийный номер:** 2 байта (uint16_t)
- **Полезная нагрузка:** Структура `TafcoTinyProtocol` (размер 5 байт)

**Поля:**
| Поле          | Размер (байт) | Описание                              |
|-------------- |-------------- |---------------------------------------|
| Код           | 1             | Тип пакета (0x11)                     |
| Серийный номер| 2             | Короткий серийный номер устройства    |
| Payload       | 5             | Структура данных датчиков             |

**Формирование:**
- Для заполнения структуры используется функция `TafcoTinyProtocol_Create(metrics)`.
- Серийный номер получается через `ModemConfig::GetSerialNum()` и приводится к 2 байтам.

**Кодирование ошибочных значений:**
- Если значение напряжения некорректно (NaN в коде), оно кодируется как `0xFF` в структуре протокола.
- При декодировании значение `0xFF` в поле напряжения интерпретируется как NaN (ошибка/некорректное значение).
- Если значение температуры некорректно (установлено в -100.0 в коде), оно кодируется как -100.0 в структуре протокола.
- При декодировании значение -100.0 в поле температуры интерпретируется как ошибка/некорректное значение.

---

## 5. Примечания
- Фактическая структура `TafcoTinyProtocol` определяется отдельно и может изменяться.
- Используемый протокол выбирается на этапе компиляции с помощью одной из директив препроцессора в начале `PacketWrapper.cpp`.
- Код рассчитан на встраиваемые системы с жёсткими ограничениями по размеру.
